pip กับ venv ต่างกันยังไง และทำไมถึงต้องมี activate

2026-11-02

ตอนทำเว็บนี้ ผมเขียนสคริปต์ Python ตัวเล็ก ๆ (build.py) ที่แปลงไฟล์ Markdown เป็น HTML สคริปต์ใช้แพ็กเกจ markdown ตัวเดียว แต่พอรัน python3 build.py กลับเจอ error

ModuleNotFoundError: No module named 'markdown'

ทั้งที่ติดตั้งไปแล้ว นี่คือที่มาของโพสต์นี้ครับ

pip คืออะไร

pip คือเครื่องมือดาวน์โหลดแพ็กเกจ Python จากคลังกลางชื่อ PyPI มาไว้ในเครื่อง

pip install markdown

คำสั่งนี้ดาวน์โหลดแพ็กเกจ markdown แล้วเก็บไว้ในโฟลเดอร์ site-packages ของ Python ตัวที่ pip ผูกอยู่ เมื่อสคริปต์เขียนว่า import markdown Python ก็จะไปหาในโฟลเดอร์นั้น

จุดสำคัญคือ แพ็กเกจถูกติดตั้งให้ "Python ตัวหนึ่ง" ไม่ได้ติดตั้งให้ทั้งเครื่อง

ปัญหาของการ pip install ลงเครื่องตรง ๆ

ถ้าติดตั้งทุกอย่างลง Python ตัวเดียวของเครื่อง จะเจอปัญหาเหล่านี้

  • โปรเจกต์ A ต้องการแพ็กเกจเวอร์ชัน 1 แต่โปรเจกต์ B ต้องการเวอร์ชัน 2 ติดตั้งได้แค่เวอร์ชันเดียวต่อหนึ่ง Python
  • แพ็กเกจเก่าที่ไม่ได้ใช้แล้วสะสมเต็มเครื่อง และไม่รู้ว่าอันไหนของโปรเจกต์ไหน
  • บางเครื่อง (เช่น Python ที่ติดตั้งผ่าน Homebrew บน macOS) ปฏิเสธการติดตั้งแบบนี้เลย โดยตอบ error: externally-managed-environment เพราะไม่อยากให้ผู้ใช้ไปเปลี่ยนแพ็กเกจที่ระบบพึ่งพาอยู่

venv คืออะไร

venv สร้าง "Python อีกชุดหนึ่ง" ไว้ในโฟลเดอร์ของโปรเจกต์ มีที่เก็บแพ็กเกจเป็นของตัวเอง

python3 -m venv .venv
.venv/bin/pip install markdown

บรรทัดแรกสร้างโฟลเดอร์ .venv/ ส่วนบรรทัดที่สอง ติดตั้ง markdown ลงใน Python ของ .venv ไม่ได้ติดตั้งลง Python ของเครื่อง โปรเจกต์แต่ละอันจึงมีชุดแพ็กเกจของตัวเอง ไม่ชนกัน

ทำไมต้อง activate

นี่คือจุดที่ผมสงสัยที่สุด python3 ที่พิมพ์ในเทอร์มินัลคือ Python ของเครื่อง ซึ่งไม่รู้จัก .venv/ เลย ตอนนั้นจึงมีสามวิธีที่จะใช้ Python ของ .venv

คำสั่ง Python ที่ถูกเรียก เจอ markdown ไหม
python3 build.py ของเครื่อง ไม่เจอ
.venv/bin/python build.py ของ .venv เจอ
source .venv/bin/activate แล้ว python build.py ของ .venv เจอ

activate ไม่ได้ทำอะไรลึกลับ มันแค่ทำให้คำว่า python ในเทอร์มินัลนั้น ชี้ไปที่ Python ของ .venv แทน และมีผลเฉพาะหน้าต่างเทอร์มินัลนั้น (เปิดหน้าต่างใหม่ก็ต้องทำซ้ำ) เลิกใช้ได้ด้วย deactivate

เลือกอะไรดี

venv แลกความสะอาดของเครื่องกับขั้นตอนเพิ่มตอนรัน

  • มีหลายโปรเจกต์ หรือแพ็กเกจหลายตัว: ใช้ venv ปัญหาเวอร์ชันชนกันเจอจริงและแก้ยาก
  • โปรเจกต์เดียว แพ็กเกจน้อย บนเครื่องของตัวเอง: pip install ลงเครื่องตรง ๆ ก็ใช้ได้ ตราบที่ระบบไม่บล็อกการติดตั้ง

ผมเลือก venv สำหรับเว็บนี้ตามหลักปฏิบัติ แต่พบว่ามันเกินความจำเป็นเล็กน้อย เพราะมีโปรเจกต์เดียวและแพ็กเกจเดียว

ถ้าไม่อยากพิมพ์ยาวทุกครั้ง

  • ใช้ .venv/bin/python build.py ได้เลยโดยไม่ต้อง activate
  • ให้สคริปต์หา venv เอง ที่เว็บนี้ build.py ตรวจว่าไม่มี markdown หรือเปล่า ถ้าไม่มีจะสร้าง .venv ติดตั้ง แล้วรันตัวเองใหม่ด้วย Python ของ .venv ผลคือพิมพ์ python3 build.py ได้ตามปกติ
  • เครื่องมืออย่าง uv จัดการ venv ให้อัตโนมัติ (ผมยังไม่ได้ลองใช้)

ข้อควรจำ

  • ใส่ .venv/ ไว้ใน .gitignore เสมอ ไม่ต้อง commit ขึ้น git
  • เก็บรายชื่อแพ็กเกจไว้ในไฟล์ requirements.txt (สร้างด้วย pip freeze > requirements.txt) คนอื่นหรือตัวเองในอนาคตจะติดตั้งได้ด้วย pip install -r requirements.txt
  • ถ้าเจอ ModuleNotFoundError ทั้งที่ติดตั้งแล้ว สงสัยไว้ก่อนว่า Python ที่รันกับ Python ที่ pip ติดตั้งให้ คนละตัวกัน ตรวจได้ด้วย which python3 และ python3 -m pip --version

python pip venv
